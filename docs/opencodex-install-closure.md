# OpenCodex 跨平台安装闭环

## 目标

用户从 Codex Manager 点击一次即可完成：环境识别、OpenCodex 安装、服务启动、供应商授权、模型同步、Codex 配置写入和可用性验证。

## 最优路径

1. 优先识别 Manager 已安装的自带运行时组件。
2. 没有组件时，下载当前系统和 CPU 对应的组件包；组件内包含 Node，不依赖用户环境。
3. 组件下载不可用时，如果本机已有 Node 18+ 和 npm，则安装到 Manager 私有目录，不污染全局环境。
4. 已存在系统 OpenCodex 时直接复用，但仍执行版本、服务健康和模型目录检查。
5. 安装后等待服务真正进入 ready，再进入授权。
6. 授权后必须同时满足：账户已返回、路由不为空、模型目录已生成、OpenCodex 健康检查通过、Codex 已指向本机代理。
7. 任一步失败都保留原 Codex 配置，并给出可重试的具体原因。

## 平台边界

- macOS：Apple Silicon、Intel。
- Windows：x64、ARM64。
- Linux：x64、ARM64；需要发布对应的自带运行时组件。
- 其他系统或未知 CPU：明确标记不支持，禁止误下载其他平台组件。

## 验收标准

- 全新用户目录、无 Node/npm、无 OpenCodex：组件下载后可启动并进入授权。
- 已有 Node/npm、无 OpenCodex：组件下载失败时可走私有 npm 安装。
- 已有系统 OpenCodex：识别并复用，不重复安装。
- 组件残缺或损坏：重新校验、解压并恢复。
- 服务启动慢：等待 ready，不把“命令已返回”误判为安装完成。
- 网络失败、校验失败、平台不支持：错误可读，原配置不受影响，可直接重试。
- 授权完成但账户、路由、模型目录或健康状态缺失：不显示成功。

## 当前交付风险

- Linux 自带运行时组件只有在构建并发布到组件清单后，才能覆盖“完全空环境”。代码支持不等于线上组件已可下载。
- macOS/Windows/Linux 的最终闭环都需要在对应真实系统上执行一次干净环境冒烟测试。
