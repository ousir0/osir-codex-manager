# Codex Manager 产品与官网整体规划

版本：v0.5.6 规划底稿

## 1. 规划目标

建立一条一致的信息链：用户第一次看到产品，能理解它是什么；能选择正确安装包；能按用户手册完成配置；需要 API 时能进入 OSIR API；后续能收到 Manager 更新。

所有页面都围绕三个用户问题组织：

1. 我应该下载什么？
2. 安装后下一步怎么做？
3. 遇到 API、模型、主题或更新问题时去哪处理？

## 2. 产品定位

### 对外一句话

Codex Manager 是官方 Codex 桌面应用的本地管理器：负责安装、更新、配置、多模型连接、主题和恢复。

### 用户得到的结果

- 不需要自己判断 macOS / Windows 安装包；
- 不需要手动维护 Codex 更新和本地配置；
- 不需要把普通 API Key、生图 API Key 和多模型路由混在一起；
- 不需要修改 Codex 应用文件就能切换主题；
- 更新失败时可以保留旧版本并恢复配置。

### 产品边界

- Manager 不重新打包官方 Codex 应用；
- Manager 不上传用户对话、工作区、API Key 或本地配置；
- OSIR API 是独立的 API 服务入口，不等同于 Manager 本体；
- OpenCodex 是可选的本地多模型运行组件，不应被描述为 Codex 官方组件。

## 3. 信息架构

### 官网一级导航

建议固定为：产品能力、下载、用户手册、OSIR API、GitHub。主题放入产品能力，不单独占用一级导航。

### 页面结构

| 页面 | 主要任务 | 用户看完要做什么 |
| --- | --- | --- |
| 首页 | 解释产品价值和安全边界 | 判断是否适合自己 |
| 下载页 | 按系统和架构提供正式包 | 下载正确安装包 |
| 使用手册 | 从安装到配置、更新、故障处理 | 完成一次可用配置 |
| API 服务页 | 解释 OSIR API 能调用什么、如何进入控制台和文档 | 创建 Key 或查看 API 文档 |
| GitHub | 源码、版本、Issue、发布资产 | 查看代码或精确版本 |

官网 app.osirclaw.com 负责 Manager；API 网站 api.osirclaw.com 负责 API 服务。两者在导航栏互相链接，但不混淆产品名称。

## 4. 视觉方向

设计主题：可信的本地 AI 工作台。

- 主背景：暖白和浅灰，保持说明页可读性；
- 主色：Codex 蓝，用于下载、选中、更新状态；
- 辅色：OSIR API 青蓝，用于 API 服务入口；
- 状态色：绿色表示已验证，橙色表示需要处理，红色表示阻塞；
- 中文标题使用现有思源宋体，英文标题使用 Fraunces；
- 导航使用统一 16–18px 线性图标；
- 真实界面示意优先于抽象装饰；
- 动效只用于首屏进入、下载选择和流程状态。

导航图标建议：产品能力使用网格，下载使用向下箭头，手册使用书本，OSIR API 使用连接节点，GitHub 使用官方 mark，语言切换使用地球图标。

## 5. 首页内容顺序

1. 首屏：说明 Manager 是什么、适合谁、下载和手册入口；
2. 产品能力：安装更新、配置多模型、主题恢复；
3. OSIR API 独立入口：控制台、模型市场、API 文档；
4. 主题展示：只作为能力证明，不抢主线；
5. 下载：版本、系统、架构、校验说明；
6. 用户手册：中文和 English；
7. GitHub、隐私和许可证。

## 6. 文档体系

- GitHub README：项目定位、功能、下载、快速开始、开发和边界；
- 中文用户手册：用户从安装到故障处理；
- English user guide：与中文章节保持一致；
- 语言切换说明：Manager、官网和 GitHub 文档的切换方式；
- 功能说明：Manager 自更新、OpenCodex、发布与签名；
- 发布说明：每个版本的用户可验证变化。

## 7. 发布策略

正式发布必须同时满足：Mac 和 Windows 四个架构资产完成，GitHub Release 已发布，updater latest.json 已生成并校验，网站镜像已推进到同一版本，官网下载链接和 API 入口已回读，README 与用户手册没有旧版本残留。

如果网站 promotion 凭据缺失，只发布 GitHub Release，不应伪造网站“最新版本”状态。

## 8. 执行顺序

1. 完成中英文用户手册；
2. 以用户手册为内容源重写 README；
3. 修正官网下载版本和 API 入口；
4. 重构官网首页与导航视觉；
5. 增加独立使用手册页面；
6. 完成 Mac / Windows 正式包和网站回读；
7. 更新 GitHub Release 说明和网站发布状态。
