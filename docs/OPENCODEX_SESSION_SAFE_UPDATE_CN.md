## 问题与修复

- 启用时 Codex 仍使用外部供应商，OpenCodex 同步可能成功返回但跳过目录生成。先备份并转移配置归属，再同步、校验，失败恢复。
- 父页面完成启用后子面板保留旧状态；同步父子状态并阻止旧请求覆盖新结果。
- 已启动不等于已启用。按钮按组件安装、服务就绪和配置接管分别显示；错误保持可见。
- Manager 自动更新重载会重启正在转发请求的 OpenCodex，旧逻辑还强制重启 Codex。更新时检测到 Codex 运行即暂缓，保留待处理状态，移除强制重启参数。

## 当前执行边界

本任务只在仓库中修改、测试、构建并发布更新。当前机器不运行真实启用示例、不启动开发版 Manager、不安装更新、不重启 Codex/OpenCodex、不改写真实用户配置或会话索引。回归测试使用临时文件和模拟接口。

自动重载会在 Codex 关闭后的 Manager 启动或状态检查中再次尝试；用户通过 Manager 主动重启时，在 Codex 退出后、重新启动前处理。直接从系统启动 Codex 而未给 Manager 留出处理时间时，可能继续使用旧配置，待下次安全时机再同步。
