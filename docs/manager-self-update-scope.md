# Codex Manager 自更新闭环：范围与边界

> 状态：方案底稿，供下一版本开发和发布验收使用。
>
> 目标：已安装用户在新版本发布后，由 Manager 主动检测并通过弹窗完成下载、校验、安装和重启，不要求用户重新打开官网下载安装包。

## 1. 结论

下一阶段只建设 Codex Manager 自身更新，不把 Codex 客户端更新、OpenCodex 组件更新和官网手动下载混在同一条用户流程里。

用户流程：

已安装 Manager → 启动或定时检查 latest.json → 发现更高版本 → 弹窗展示版本和说明 → 用户确认 → 下载并校验 → 安装并重启 → 启动后确认版本已变更 → 显示成功或失败。

## 2. 本期范围

### 包含

- macOS Apple Silicon、macOS Intel、Windows x64、Windows ARM64 自更新；
- 启动后后台检查一次；
- 按设置执行周期检查；
- 应用级更新状态，所有页面共享；
- 统一更新弹窗；
- 用户确认后直接下载、签名校验、安装和重启；
- 更新后重新读取版本并确认升级结果；
- “稍后提醒”和“跳过此版本”；
- 更新失败时保留旧版本可用。

### 不包含

- 不自动安装更新，用户必须在弹窗中确认；
- 不修改 Codex 客户端自身的更新逻辑；
- 不在本期自动更新 OpenCodex 多模型组件；
- 不静默修改 Codex 配置、API Key、主题或会话数据；
- 不覆盖同版本发布包，修复必须提升版本号；
- 不要求用户重新登录、重新授权或重新配置供应商。

## 3. 版本与发布边界

- 当前版本来自 Tauri 应用版本；
- 最新版本来自 https://app.osirclaw.com/manager/latest.json；
- 下载地址来自清单中对应平台的 updater 工件；
- 信任根来自 src-tauri/tauri.conf.json 的 updater 公钥。

每次包含客户端代码的修改，必须：

1. 同步 package.json、package-lock.json、src-tauri/Cargo.toml、src-tauri/Cargo.lock、src-tauri/tauri.conf.json 的版本；
2. 创建新的 vX.Y.Z Release；
3. 生成四个平台安装包、updater 包、签名和 latest.json；
4. 完成本地哈希和签名验证；
5. 推进 app.osirclaw.com/manager/latest.json；
6. 回读官网页面、更新清单和四个平台下载地址。

同一个版本不可重复覆盖，避免缓存和不可变发布资产不一致。

## 4. 客户端行为

### 启动检查

- 主窗口和基础状态加载完成后后台检查一次；
- 检查失败不阻断打开主界面；
- 已提示过的版本，本次会话不重复打扰；
- 跳过某版本后，只跳过该版本，更高版本仍然提醒。

### 周期检查

- 复用现有“定时检查”设置；
- 限制最短检查间隔，避免高频请求；
- 周期检查只负责发现更新，不自动安装；
- 网络错误只记录或轻提示，不影响正常使用。

### 更新弹窗

至少显示：当前版本、新版本、更新说明、“立即更新”、“稍后提醒”和“跳过此版本”。

更新进行中必须禁止重复点击、重复安装和关闭关键流程。

### 安装与重启

1. 用户确认后再次获取更新清单；
2. 确认目标版本仍存在且高于当前版本；
3. 下载对应平台 updater 包；
4. 校验签名和目标版本；
5. 调用 Tauri updater 安装；
6. 重启 Manager；
7. 重启后确认当前版本等于目标版本；
8. 显示成功、失败或回滚结果。

## 5. 数据与安全边界

更新器可以替换 Manager 应用包，但不能删除或重置：

- Codex 会话和历史记录；
- OpenCodex 配置、模型目录和关联备份；
- API Key、OAuth 状态和订阅信息；
- 用户主题、MCP 和其他本地设置。

更新包必须在安装前完成签名校验。清单、下载地址或版本信息发生变化时，必须中止安装。

## 6. 异常处理

| 场景 | 用户结果 | 数据结果 |
| --- | --- | --- |
| 清单不可达 | 不打断使用，可稍后重试 | 不变更本地数据 |
| 没有更高版本 | 不显示弹窗 | 不变 |
| 签名校验失败 | 提示更新包无效 | 不安装 |
| 下载中断 | 提示重试 | 保留当前版本 |
| 安装失败 | 提示失败并保留当前版本 | 不删除用户数据 |
| 重启后版本未变化 | 显示更新未生效 | 不重复静默安装 |
| 用户跳过版本 | 当前版本不再提示 | 更高版本继续提示 |

## 7. 验收标准

### 自动提醒

- 旧版本启动后能后台发现新版本；
- 不进入“关于”页也能看到更新弹窗；
- 启动检查和周期检查遵守设置；
- 四个平台行为一致，差异只限安装包格式和系统重启方式。

### 直接更新

- 点击“立即更新”后无需手动打开官网；
- 下载地址来自 latest.json，不是前端硬编码；
- 更新前完成签名校验；
- 安装后 Manager 自动重启；
- 重启后版本号变为目标版本。

### 安全回退

- 更新失败时旧版本仍能启动；
- 用户会话、配置和 OpenCodex 数据不丢失；
- 不会因重复点击产生多个安装任务；
- 跳过旧版本不会阻止未来更高版本提示。

### 发布验证

- GitHub Release 四个平台资产齐全；
- latest.json 版本和签名正确；
- 官网版本化下载地址和 latest 地址可访问；
- 用旧版 Manager 完成至少一次真实升级测试；
- 四个平台至少完成一次清单解析和安装路径验证。

## 8. 当前实现差距

当前代码已经具备 Tauri updater 检查、公钥和签名校验、安装命令、前端 ManagerUpdateProvider、启动检查、周期检查、稍后提醒和跳过版本状态。

下一版本重点补齐：

- 确认启动检查在所有桌面入口都挂载；
- 确认更新状态覆盖所有页面，而不是只依赖“关于”页；
- 完善重启后的成功或失败展示；
- 更新期间锁定导航和重复操作；
- 完成四个平台旧版升级 smoke test。

## 9. 推荐实施顺序

1. 固化应用级更新状态和统一弹窗；
2. 接入启动检查和周期检查；
3. 完善安装中、重启中、成功、失败状态；
4. 补充四个平台测试和旧版升级 smoke test；
5. 发布一个专门验证自更新闭环的版本；
6. 再把后续业务功能和自更新功能合并发布。
